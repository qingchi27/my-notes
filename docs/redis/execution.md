# Redis 执行模型


---

## 1. Redis 是单线程还是多线程？

**答：** Redis 不是简单的单线程，也不是完全多线程。

### 1.1 Redis 6.0 之前

核心执行模型是**单线程**：

- 接收客户端请求
- 执行 Redis 命令
- 返回执行结果

都由一个线程完成。

### 1.2 Redis 6.0 之后

引入多线程，但职责分离：

- **网络 IO 处理**：多线程
- **Redis 命令执行**：仍然是单线程

准确说法：

> Redis 6.0 之后采用 **IO 多线程 + 单线程执行命令** 的模型。


---

## 2. Redis 为什么选择单线程执行命令？

**答：** 主要有以下原因。

### 2.1 性能瓶颈通常不在 CPU

Redis 基于内存操作：

- 数据读取速度非常快
- 单个命令执行耗时很短

大部分场景瓶颈在：

- 网络 IO
- 内存访问

而不是 CPU 计算。

### 2.2 避免多线程竞争

如果多个线程同时执行 Redis 命令，需要解决：

- 数据竞争
- 锁竞争
- 线程同步

会增加系统复杂度，还可能降低性能。

单线程执行的好处：

- 无锁
- 无线程切换开销
- 执行顺序明确

### 2.3 保证命令执行的原子性

命令串行执行，例如：

```text
INCR count
```

不会出现多个线程同时修改同一数据导致的一致性问题。


---

## 3. Redis 单线程性能如何？

**答：** Redis 基于内存存储，单节点性能非常高。

官方测试量级（约）：

- 读取：约 **10 万 QPS+**
- 写入：约 **10 万 QPS** 左右

实际性能受以下因素影响：

- 硬件配置
- 网络环境
- 数据结构
- 命令复杂度


---

## 4. Redis 单线程为什么还能这么快？

**答：** 高性能主要依靠以下几个方面。

### 4.1 基于内存存储

数据主要在内存中，避免磁盘 IO：

- 访问更快
- 延迟更低

### 4.2 高效的数据结构设计

针对不同场景设计底层结构：

| 数据类型 | 底层结构 |
|---|---|
| String | SDS |
| List | QuickList |
| Set | IntSet / HashTable |
| Hash | ListPack / HashTable |
| ZSet | SkipList + HashTable |

通过不同结构：

- 节省内存
- 提升访问效率

### 4.3 IO 多路复用

采用事件驱动模型，借助：

- `epoll`
- `select`
- `kqueue`

一个线程可以同时处理大量客户端连接。

### 4.4 单线程避免锁竞争

命令串行执行，不需要：

- 加锁 / 解锁
- 线程同步

降低额外开销。

### 4.5 异步持久化

支持 RDB、AOF，持久化通常由**后台线程 / 子进程**完成，不阻塞主请求处理路径。

注意：持久化并非完全无影响，仍可能带来一定 IO 压力。


---

## 5. Redis 6.0 为什么引入多线程？

**答：** 主要为了提升**网络 IO 处理能力**，提高多核 CPU 利用率。

随着客户端连接数增加，瓶颈逐渐从「CPU 执行命令」转向：

- 网络数据读取
- 请求解析
- 数据返回

因此引入 IO 多线程。


---

## 6. Redis 6.0 多线程负责哪些工作？

**答：** 主要负责网络侧读写，**不负责并行执行命令**。

### 6.1 请求读取

负责：

- 从客户端读取数据
- 网络数据解析

流程示意：

```text
客户端发送 GET user:1
        ↓
IO 线程读取请求
        ↓
主线程执行命令
```

### 6.2 响应返回

负责将执行结果发送给客户端：

```text
主线程执行完成
        ↓
IO 线程发送结果
        ↓
客户端收到响应
```

### 6.3 命令执行仍然单线程

完整流程：

```text
客户端请求
        ↓
IO 多线程读取请求
        ↓
单线程执行 Redis 命令
        ↓
IO 多线程返回结果
```

注意：Redis 多线程**不是**多个线程并行执行 Redis 命令。


---

## 7. Redis 6.0 多线程默认开启吗？

**答：** **默认关闭**，需要手动配置开启。

配置示例：

```conf
# IO 线程数量
io-threads 4

# 是否用 IO 线程读请求
io-threads-do-reads yes
```

开启后，Redis 使用多个线程处理网络 IO。


---

## 8. 面试总结

### 8.1 Redis 执行模型

**Redis 6.0 之前：**

```text
单线程：网络 IO + 命令执行 + 返回结果
```

**Redis 6.0 之后：**

```text
IO 多线程读请求
        ↓
单线程执行命令
        ↓
IO 多线程返回结果
```

### 8.2 Redis 为什么快？

1. 基于内存存储  
2. 高效的数据结构  
3. IO 多路复用  
4. 单线程避免锁竞争  
5. 异步持久化  

### 8.3 Redis 6.0 为什么增加多线程？

不是为了让多个线程同时执行 Redis 命令，而是：

> 用多线程处理网络 IO，提高多核 CPU 利用率，缓解高并发连接下的网络瓶颈。
