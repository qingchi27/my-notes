# 语言特点与运行原理

## 1. Java 语言有什么特点？

- **面向对象**：支持封装、继承、多态
- **跨平台**：源码编译成字节码，由不同平台的 JVM 执行
- **自动内存管理**：JVM 提供垃圾回收，一般不需要手动释放对象内存
- **编译与解释结合**：先由 `javac` 编译成字节码，运行时由解释器和 JIT 执行
- **强类型语言**：变量和表达式有明确类型
- **丰富的标准类库和生态**
- **安全性**：字节码验证；没有显式指针运算
- **多线程支持**：内置 `Thread` 与 `java.util.concurrent`

另外：Java 是 **值传递**。对象参数传递也是值传递，传递的是对象引用的副本。

除 `Object` 本身之外，Java 中的类最终都继承自 `Object`。不要说「所有的类都是 Object 的子类」——`Object` 自己不是。

---

## 2. Java 和 C++ 有什么区别？

抓住核心即可，不必背十条。

| | Java | C++ |
|---|---|---|
| 运行方式 | JVM 运行字节码 | 编译成平台相关机器码 |
| 跨平台 | 一次编译，多平台 JVM 运行 | 通常需针对不同平台编译 |
| 内存 | 有 GC | 手动管理 / RAII |
| 指针 | 没有显式指针运算 | 支持指针 |
| 继承 | 类单继承 + 接口 | 支持类多继承 |
| 产物 | 字节码 + JVM | 原生机器码 |

不要说「Java 一定比 C++ 慢」。现代 JVM 有 JIT，会根据运行时信息优化热点代码，某些场景下性能可以非常接近甚至达到 C++ 的水平。

---

## 3. Java 为什么可以跨平台？

源码先通过 `javac` 编译成平台无关的字节码 `.class`。不同操作系统提供对应平台的 JVM，由 JVM 把字节码转换成当前平台的机器指令。

```text
Java 源码
   ↓ javac
字节码 .class
   ↓
Windows JVM / Linux JVM / macOS JVM
   ↓
对应平台机器码
```

常说「一次编译，到处运行」。更准确是：**一次编译，多平台 JVM 运行。** JVM 是跨平台的桥梁。

---

## 4. JVM、JDK、JRE 有什么区别？

| 组件 | 全称 | 作用 |
|---|---|---|
| JVM | Java Virtual Machine | 加载 Class、执行字节码、内存管理、GC、JIT |
| JRE | Java Runtime Environment | JVM + 运行时类库，主要用于运行程序 |
| JDK | Java Development Kit | JRE + 开发工具（`javac`、`java`、`javadoc`、`jdb`、`jar` 等） |

关系：`JDK ⊃ JRE ⊃ JVM`

现代 JDK 已经不再单独发布传统意义上的 JRE。面试可补一句：JRE 是传统 Java 版本中的运行时环境概念，现代 JDK 发行版通常直接提供运行程序所需的完整环境。

## 5. 什么是字节码？为什么使用字节码？

字节码是 JVM 能够理解和执行的中间代码，通常存在 `.class` 文件中。可用 `javap -c Hello.class` 反汇编查看。

```text
.java
  ↓ javac
.class
  ↓ JVM
解释执行 / JIT 编译
  ↓
机器码
```

使用字节码的主要好处：跨平台、方便 JVM 做运行时优化、统一安全检查、利于生态和工具链发展。

---

## 6. 为什么说 Java 是编译与解释并存？

不要说「`.class` 转换成机器码就是解释」。JVM 并不是单纯解释执行。

标准回答：Java 源码首先由 `javac` 编译成字节码；JVM 运行字节码时，可以通过解释器直接解释执行，也可以通过 JIT 将热点代码编译成本地机器码后执行，因此 Java 是一种 **编译与解释相结合** 的语言。

---

## 7. 为什么不全部使用 AOT？

AOT（Ahead Of Time）：提前编译成机器码。JIT（Just In Time）：运行时把热点代码编译成本地机器码。

```text
传统 JVM：源码 → 字节码 → JVM → 解释 / JIT → 机器码
AOT：     源码 → 提前编译 → 机器码
```

JIT 的核心优势是可以根据程序 **真正运行时的数据** 做优化。例如某分支 99% 走 `methodA()`，JIT 可以针对真实路径做激进优化。

| | 优点 | 缺点 |
|---|---|---|
| AOT | 启动快、无需运行时编译、内存可能更低 | 缺少运行时信息，动态优化弱 |
| JIT | 可按真实运行情况优化，跑得越久效果可能越好 | 启动阶段有解释 / 编译开销 |

传统 Java 服务更依赖 JIT；现代 Java 也支持 AOT（如 GraalVM Native Image）。两者各有适用场景。
